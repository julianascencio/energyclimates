NEW · EVERYDAY NAMES

Three systems. Three useful views.

These new profiles are experimental additions to KGPV. Their versioned rules are open, editable and the same in Python and this website. The names describe climate exposure; they are not equipment ratings.

☀

PV · sunlight + temperature

Names such as “Sunny · mild” combine annual sunlight with ambient temperature weighted toward the months that receive more sunlight. A separate seasonality indicator shows how unevenly sunlight is spread through the year.

☀ + ▤

PV + battery · seasonal supply

Names such as “Seasonal sun · cold winters” combine weak-month sunlight with winter and summer temperature exposure. Weak-month sunlight helps identify seasonal supply gaps; it does not calculate storage duration.

▤

Battery · thermal exposure

Names such as “Hot summers” describe the coldest and warmest monthly mean air temperatures. Sunlight does not affect this classification. Cell temperature and thermal management require equipment and operating data.

See the thresholds, ML diagnostics and limitations
Climate signalCurrent experimental rules
Annual horizontal sunlightLow ≤ 1,130; moderate ≤ 1,560; sunny ≤ 2,070; very sunny > 2,070 kWh/m²/year. Uses the KGPV irradiation thresholds.
Sunlight-weighted air temperatureCool < 10°C; mild 10–25°C; hot > 25°C. This is ambient air, not module temperature.
Weak-month sunlightWeakest month’s daily GHI / annual daily mean: strongly seasonal < 35%; seasonal 35–<75%; steady ≥ 75%.
Battery thermal contextCold winters: coldest monthly mean < 5°C. Hot summers: warmest monthly mean > 30°C. Otherwise “Mild year-round” refers to monthly averages only.

The new temperature and seasonality boundaries are provisional screening choices. Daily extremes, snow, dust, humidity, wind, module design, battery chemistry, state of charge, cycling and controls can change actual performance. These profiles do not estimate yield, cooling power, battery size, life, safety or financial return.

The independent atlas ML models use standardized climate features and area-weighted MiniBatch K-means: eight PV groups, eight hybrid groups and four battery groups. Model selection is provisional. Evaluation holds out complete 10° geographic blocks, with scaling fitted only on training blocks. The final map is then fitted on all complete cells.

ML group names describe the average conditions in each cluster. Cluster numbers have no ranking. “Outside typical training conditions” flags unusually distant input; assignment separation is a distance measure, not a probability.

To test practical value, the Python software also evaluates a separate measured or simulated outcome using spatial cross-validation and a mean baseline. No such yield or battery outcome has been supplied here, so no performance advantage is claimed.

Two climate dimensions.
Twelve published zones.

Temperature and precipitation form six climate groups. Annual global horizontal irradiation adds four irradiation levels. The published merge table reduces the 24 combinations to 12 KGPV zones.

SOURCE QUALITY FINDING

The published CSV needs a label review.

The original file labels the cell at 55°S, 68°W “AK” (tropical, very high irradiation), while its annual irradiation is 946 kWh/m² and mean air temperature is 5.0°C. A label-order mismatch is suspected. Original labels are preserved, and no zone-change statistics are derived from them.

The original file only spans 55°S to 70°N. Empty cells remain empty. Recalculated climate layers use their own valid land coverage.

What changed?

CRU TS 4.01 → 4.10. GPCC v2018 → Monthly v2025. ERA-Interim → ERA5, still produced by ECMWF. The full classification uses 1996–2022; the temperature and precipitation refresh uses 1996–2025.

Differences include dataset revisions and the reanalysis transition as well as climate evolution. They are not a clean estimate of climate change alone.

What the map does not resolve

A 0.5° cell is about 56 km north–south. Coastal areas, islands and mountain microclimates need finer local analysis. The original PV metrics describe the paper’s typical c-Si system; they have not been recalculated for current modules.

Future IPSL projections and a new population-based class ranking have not been calculated. The original 12-zone merge table is retained.

START WITH THE INCLUDED EXAMPLES

One command to classify.

Clone or download the GitHub repository, open a terminal in energyclimates and run:

python -m pip install -e .
energyclimates classify examples/monthly-climate.csv \
  --mapping examples/monthly-mapping.json

You get plain-language PV, PV + battery and battery profiles, a feature table, map points and a run manifest. Regular grids also get GeoTIFFs.

MACHINE LEARNING INCLUDED

Train it. Use it. Inspect it.

energyclimates train examples/global-climate-features.parquet \
  --technology pv --clusters 8 --area-weighted \
  --output my-pv-model.json

energyclimates predict examples/monthly-climate.csv \
  --mapping examples/monthly-mapping.json \
  --model my-pv-model.json

Change pv to hybrid or bess. The download includes 67,420 real climate-feature rows and three trained JSON models. Model diagnostics use geographic holdouts.

Use data from any provider with the required variables and declared units: CSV, Parquet, NetCDF, Zarr or 12-band monthly GeoTIFFs. Time series can be hourly, daily or monthly; incomplete periods remain unclassified. Dataset mappings, API and full instructions ↓

Full run instructions ↓

One method, inspectable outputs

Monthly temperature and precipitation are aligned with ECMWF irradiation on a 0.5° grid. Every month in the selected period must exist. Missing cells stay masked; no-data is never classified as polar or low irradiation.

ERA5 monthly radiation is converted from a mean daily accumulation into monthly energy using the actual days in each month, including leap years.
